# CYRO — 🛡️ Intelligent Cybersecurity Platform

منصة أمن سيبراني تفاعلية تعمل **محليًا بالكامل ودون إنترنت**: أدوات فحص، مركز عمليات SOC، مختبر محاكاة هجمات، **خريطة هجمات مباشرة**، ومحرك كشف واستجابة دفاعية آلية.

> كلمة «الذكية» تعني التحليل والاستجابة الآليين بقواعد معلنة وليست نموذج تعلم آلي.

## التشغيل على Windows
1. ثبّت Python 3.10+ (فعّل Add Python to PATH).
2. انقر مرتين على `run.bat` (ينشئ بيئة افتراضية ويثبّت المكتبات ويفتح المتصفح). **المرة الأولى فقط تحتاج إنترنت لتثبيت المكتبات**، وبعدها يعمل دون إنترنت.
3. أو يدويًا: `pip install -r requirements.txt` ثم `python app.py` ثم افتح http://127.0.0.1:5000

## خريطة الهجمات
خريطة عالم منقّطة تعمل دون إنترنت (بيانات Natural Earth، ملك عام). عند كل حدث يرسم النظام قوسًا من **نقطة المصدر** إلى **الخادم المحمي**: أحمر إن نفذ الهجوم، أخضر إن حُظر، أزرق للمستخدم المحلي. تظهر في لوحة التحكم ومركز SOC والمختبر، وتُقرأ من الأحداث المخزنة في قاعدة البيانات.
- مصادر المحاكاة عناوين اختبار محجوزة ليس لها موقع حقيقي، لذلك تُعرض كنقاط توضيحية موسومة SIM-01…SIM-16، **ولا تمثل دولًا أو مواقع فعلية**.
- لا تُرسم الفحوصات الحقيقية للأدوات على الخريطة لأن موقعها غير معروف، ولا يُختلق لها موقع.
- موقع الخادم المحمي يُضبط في `config.py` عبر `LAB_SERVER_GEO = (خط العرض, خط الطول)`.

## مختبر الاتصال الآمن (Secure Communication Lab)
مرسل ← قناة ← مهاجم ← مستقبل. اكتب رسالة وأرسلها وشاهد الحزمة تتحرك، واختر هجومًا: تنصّت، تعديل، إعادة إرسال، انتحال، أو وسيط MITM، ثم فعّل طبقات الحماية: AES-256-GCM، توقيع ECDSA، تبادل مفاتيح موثّق، ومنع إعادة الإرسال.
- التشفير حقيقي (Web Crypto في المتصفح) ولا مكتبات جديدة؛ المهاجم كائن محلي لا يرسل شيئًا خارج الجهاز.
- كل حدث يُرسل لمحرك CYRO (قواعد CR-CM-001..004): يكتشف ويحظر المهاجم ويُبطل المفاتيح أو يفرض التشفير ثم يتحقق، ويظهر في SOC ولوحة التحكم والخريطة. نص الرسائل لا يُخزَّن.
- يحتاج فتح الصفحة عبر localhost أو 127.0.0.1 (متطلب Web Crypto).

## تسلسل الدفاع النشط
`هجوم ← كشف ← تحليل ← إنشاء حادثة ← استجابة آلية ← تحقق ← احتواء ← تقرير`
كل مرحلة تُسجَّل بوقتها. التحقق فعلي: بعد الحظر يُرسَل حدث اختباري عبر المرشح نفسه ويجب أن يُرفض.

## سيناريو عرض مقترح (3 دقائق)
1. افتح **مختبر المحاكاة** واختر Brute Force وسرعة 1× واضغط بدء.
2. راقب الأحداث والمسار حتى «الاحتواء»، ولاحظ أن سارة (مستخدمة عادية) لم تُصنَّف مهاجمة.
3. افتح **مركز SOC ← الحوادث** وانقر الحادثة ونزّل التقرير PDF.
4. جرّب **كاشف التصيد** بلصق رسالة مشبوهة، ثم عد للوحة التحكم لترى الحادثة.

## الأمان
CSRF، تحديد معدل الطلبات، CSP صارمة، حجب localhost والشبكات الخاصة (SSRF) مع تثبيت IP عند فحص الشهادة، استعلامات SQL مُعلَّمة، حدود حجم الملفات، لا تُحفظ كلمات المرور ولا الملفات ولا نصوص الرسائل الحقيقية، ولا يُنفَّذ أي ملف.
المحاكاة: مصادر الهجوم عناوين اختبار محجوزة (RFC 5737)، ولا اتصال خارجي، وعينات الملفات نصوص خاملة في الذاكرة. الحظر والعزل يجريان في جدار حماية **محاكى** داخل قاعدة البيانات ولا يمسّان جهازك أو شبكتك.

## حدود معلنة
- التحليل قائم على قواعد (ليس نموذج ذكاء اصطناعي) وغياب المؤشرات لا يعني أن العنصر آمن.
- فاحص الروابط لا يتتبع سلاسل التحويل (Redirects) عمدًا لتجنب الاتصال بمواقع غير موثوقة؛ يكتشف المختصرات والتحويل المضمَّن في المعاملات.
- الـ Hash يتحقق من سلامة المحتوى ولا يكشف البرمجيات الخبيثة.
- حدود قواعد الكشف مضبوطة لتناسب العرض المباشر (مذكورة في شروط كل قاعدة).
- البث المباشر بتقنية Server-Sent Events (مدمجة في المتصفح) بدل WebSocket لأنها لا تحتاج مكتبات إضافية.
- لا يوجد نظام حسابات/تسجيل دخول: التطبيق يستمع على 127.0.0.1 فقط لجهاز العرض.
- (اختياري) `python update_blocklist.py` ينزّل قائمة URLhaus المجانية مرة واحدة؛ هذه الميزة لم تُختبر على الإنترنت الحقيقي.
